# F002 RFC：AI协作——在局域网内共享助理

## 摘要

主人在「助理」页把自己的某个助理设为共享，设置信任程度、会话保留天数和同时处理的任务数。同一局域网里的其他 OpenBitFun 用户点「发现」，可以看到局域网内共享的助理（设备名 + 助理名），点击后申请使用。主人这边立即弹出确认框，确定按钮带倒计时，超时自动拒绝；主人确定后，使用者马上收到结果，这个助理进入使用者的助理列表，标明来源。使用者点开它直接对话，每个对话在主人那边是该助理名下的一个独立会话。

整个过程只在局域网内：用 Bonjour（mDNS/DNS-SD）发现，设备之间直接连接并端到端加密，不经过中继，不需要登录账号。任务的执行、会话、事件和审批仍复用 Detached Dispatch。

此外，助理之间可以相互调用：主人自己的助理，以及别人共享给主人的助理，都能被主人的其他助理当作子智能体调用。

第 6 版用这套流程替换第 5 版的「中继 + 账号连接 + AI协作页」方案，相关界面与中继跨账号能力一并删除。

## AI协作需求（基准，第 6 版）

本节是 F002 设计、实现与评审的基准。后续决策不得偏离这里，除非主人修改需求；不服务于这里的功能不保留。

1. **核心是「我的助理」**：只共享助理。助理有身份、有记忆、有工具。
2. **共享在助理上完成**：在「助理」页点助理上的共享按钮，设置信任程度、会话保留天数、同时处理的任务数，确定后该助理标为「共享中」。
3. **只在局域网内，不需要登录**：同一局域网的人点「发现」，看到共享的助理并申请使用；主人当场确认，确认框带倒计时，超时自动取消。结果直接经局域网推送，不经过中继。
4. **授权后像自己的助理一样用**：被授权的助理进入使用者的助理列表，标明来源，点开直接对话。每个对话在主人那边是该助理名下的一个独立会话，标明来源；主人可以查看过程，需要时审批。
5. **处理外部任务时能力完整**：可以使用工具、创建子智能体、调用外部智能体（如 Claude Code）。
6. **助理之间可以相互调用**：自己的助理和别人共享给我的助理，都可以被我的其他助理调用。
7. **界面以助理为主**：主人看不懂、也用不上的内部模式名不出现在界面中。

## 背景与问题

- 第 5 版要求主人先在 AI协作页创建邀请、核对指纹、选择连接的信任级别，再把助理开放给连接；使用者还要在对话里让自己的助理去调用对方的助理。2026-11-02 在两台 Mac 上的真机测试中，这条路径没有走通：
  - 对方开放了什么在界面上看不到；
  - 连接、账号登录和中继连接任一环节出问题，助理都拿不到共享的助理，而且没有提示（缺陷 B001–B005）。
- 主人希望的形态和 macOS 的「共享」/隔空投送一样：同一局域网内直接发现，对方申请，自己当场同意。
- 现有可复用的能力：
  - Detached Dispatch：目标端持有任务、会话、事件日志与权限邮箱，按游标观察，支持幂等提交、取消、追加、继续与审批。
  - 外部任务以助理身份运行、不改写助理（F002-07）。
  - 受阻时如实告知、排队（F002-08）。
  - 会话保留期限（F002-09）。
  - 设备 X25519 + HKDF 消息密钥。
- 缺失的能力：
  - 局域网发现。仓库里没有 mDNS 依赖；现有的「局域网模式」是手机配对用的本机中继，不发现其他设备。
  - 设备之间的直接通道。
  - 与账号无关的设备身份。
  - 桌面安装包缺少任务执行器：执行器是 `openbitfun` CLI，dmg 中没有（B004）。

## 目标

1. 主人在「助理」页共享或停止共享任意一个自己的助理，并在共享时设置信任程度、会话保留天数和同时处理的任务数；共享中的助理有明确标记。
2. 同一局域网的使用者点「发现」，看到可用的共享助理（设备名 + 助理名）；悬停可以查看详情；点击后申请使用。
3. 主人立即收到确认框，确定按钮带倒计时，超时自动拒绝；确定或拒绝的结果立即推送给使用者。
4. 被授权的助理出现在使用者的助理列表中，标明「来自 某某的设备」；使用者点开直接对话，可以有多个对话，对话可以随时继续。
5. 每个对话在主人那边是该助理名下标明来源的独立会话；主人可以查看与审批；助理能力完整，信任程度决定它能碰到主人的哪些东西；外部任务不改写这个助理。
6. 主人能看到谁在用自己共享的助理，并逐个撤销；使用者能把共享助理从自己的列表中移除。
7. 不登录账号也能完成共享、发现、申请、使用的全过程。
8. 助理之间可以相互调用，包括主人自己的助理和别人共享给主人的助理；调用形成环时明确拒绝。
9. 对方不在线、不在同一局域网、版本不兼容、授权已撤销、超出同时任务数时，界面与助理都明确说明原因。

## 非目标

- 跨局域网（经中继或互联网）共享助理；第 5 版的中继跨账号连接一并删除。
- 公开的助理市场，或按账号检索他人的助理。
- 同一账号的设备经中继互相调用助理（F002-02）。本机与同一局域网的自己的设备，按本流程共享即可。
- 委派编码任务、把改动以分支带回（第 4 版已删除）。
- 共享智能体模式或外部智能体本身（第 4 版已删除）。
- 计费结算、按助理隔离的记忆。
- 在手机端、IM 或 CLI 主机上共享或发现助理。

## 决策

### D1 局域网发现：Bonjour

- 共享了至少一个助理的桌面端，在局域网内广播服务 `_openbitfun._tcp`。广播内容只有：
  - 设备名；
  - 主人的显示名（取本机用户名，可修改）；
  - 设备共享公钥的指纹；
  - 通道端口；
  - 协议版本。
- 共享助理的名称和说明不放进广播，由对方连上通道后读取。
- 没有共享任何助理时不广播。
- 只有使用者打开「发现」面板时才主动浏览。已授权的共享助理只用解析来更新在线状态，不持续扫描整个网络。
- 使用纯 Rust 的 mDNS 实现，归属 services 层，由桌面端适配层启动，不依赖操作系统的 Bonjour 服务。
- macOS 15 及以上需要在 Info.plist 声明本地网络用途与 Bonjour 服务类型；首次使用时系统会请求「本地网络」权限。被拒绝时，「发现」面板说明原因，并给出打开系统设置的入口。

### D2 设备共享身份：与账号无关

- 每台设备生成一对持久的共享身份密钥（X25519），与账号和中继无关，不登录也存在。
- 显示名默认取本机用户名，可以在「发现」面板中修改。
- 授权绑定到使用者设备的共享公钥：申请时双方交换公钥，主人确定后固定下来，与隔空投送一样首次信任。之后对方公钥变化，原授权失效，需要重新申请。

### D3 局域网通道

- 设备之间建立直接连接（WebSocket over TCP）。端口只监听私有地址网段的网卡，不监听公网地址与回环以外的接口。
- 消息用双方共享密钥派生的消息密钥加密，复用现有的设备消息密钥派生方式，但使用独立的域标签。
- 申请与确认、确认结果推送、任务提交与进度观察、审批，都走这条通道。
- 握手中协商协议版本与能力。版本号相同不能代替能力声明；不兼容时，「发现」面板把该设备显示为「需要更新」。
- 未授权的设备只能读取共享助理的名称与说明，以及发出申请，不能提交任务。

### D4 共享助理（主人）

- 「助理」页的每张卡片增加「共享」按钮。点击后弹出共享设置：
  - **信任程度**：普通 / 完全信任，含义见 D8；
  - **会话保留天数**：1、7、30、90，默认 7；
  - **同时处理的任务数**：默认 2。
- 确定后卡片标「共享中 · N 人在用」。点击标记打开管理视图：修改设置，查看使用者（显示名 + 设备名 + 授权时间 + 最近使用），逐个撤销，或停止共享。
- 设置改的是该助理的共享，对所有使用者生效：
  - 信任程度从下一回合起生效；
  - 保留天数对已有会话同样生效。
- 停止共享会撤销全部授权。
- 外部智能体可能消耗主人在服务商处的额度。助理配置了外部智能体时，共享设置中提示额度与条款（例如 Claude Code 订阅登录用于他人请求可能超出订阅限定，建议改用 API Key），由主人确认一次。凭据绝不出设备。

### D5 发现与申请（使用者）

- 「助理」页标题栏的「创建助理」左边增加「发现」按钮，打开发现面板：
  - 按设备分组，显示局域网内的共享助理（设备名 + 助理头像与名称）；
  - 悬停显示详情：说明、主人显示名、设备名；
  - 每个助理显示状态：可申请 / 申请中（倒计时）/ 已在你的列表中 / 需要更新。
  - 面板为空时说明原因：没有发现共享的助理，或本地网络权限被拒绝。
- 点击「可申请」的助理即发出申请，使用者看到「等待 某某 确认」和剩余秒数。主人确定后，面板提示「已添加」，助理出现在「你的助理」列表中；被拒绝或超时，提示「未获同意」。
- 防打扰：同一设备对同一助理同一时间只能有一个申请；被拒绝或超时后 1 分钟内不能再次申请。主人可以在确认框中选择「拒绝并不再提示」，屏蔽这台设备。

### D6 确认框（主人）

- 收到申请时，主人的桌面端立即弹出模态确认框，内容为「某某（设备名）想使用你的助理『X』」，并显示申请设备的公钥指纹短码。
- 按钮为「拒绝」和「允许（60）」，允许按钮上的数字逐秒倒数，到 0 自动拒绝。
- 应用不在前台时同时发系统通知，点通知打开确认框。
- 多个申请依次排队，每个独立计时。
- 申请时主人设备不可达的，使用者立即收到「对方不在线」，不排队、不重试。

### D7 使用共享的助理（使用者）

- 被授权的助理出现在使用者「你的助理」列表中，卡片标「来自 某某的设备」，对方不在线时置灰并显示「不在线」。
- 点开即进入与它的对话界面，和与自己助理对话一致：
  - 每个对话是一个外部任务，追问延续同一会话；
  - 对话列表在该助理下面，可以随时回到旧对话继续，直到超过主人设置的保留天数；
  - 需要主人审批时，对话里显示「等待 某某 审批」；
  - 超出同时任务数时排队，并显示排队状态。
- 使用者可以把它从列表中移除，这会撤销该授权并删除使用者本地的对话记录。
- 使用者本地的对话记录只是展示副本，以主人那边的会话为准，按游标补收。离线时可以查看已收到的内容，不能发送。

### D8 信任程度（沿用第 5 版 D9 的含义，改为按共享的助理设置）

- **普通（默认）**：助理可以使用工具、创建子智能体、调用外部智能体，但目标端在工具层禁止以下操作，不依赖提示词：
  - 读取或操作本机其他会话与工作区；
  - 控制主人的桌面、浏览器或终端会话；
  - 创建定时任务或持久目标、发布对外内容、操作 OpenBitFun 自身；
  - 调用主人的其他助理。

  记忆摘要与 `USER.md` 不放进提示；文件工具读取它们须主人审批。命令执行与外部智能体按审批策略处理，界面如实说明这层保护依靠审批。
- **完全信任**：开启前显示风险并需要主人确认。开启后外部任务与主人自己的任务权限相同，包括调用主人的其他助理。
- 两种程度下，审批人、同时任务数、审计、撤销都不变。委派内容一律作为不可信输入处理。

### D9 执行与外部任务（沿用）

- 执行复用 Detached Dispatch：
  - 外部任务固定使用 `remote` 审批策略；
  - 权限请求进入主人的权限邮箱，桌面端、手机端、IM 都能审批；
  - `AskUserQuestion` 明确失败，不等待。
- 外部任务以该助理的人设运行，在独立的工作目录中执行，不改写助理：
  - 不参与记忆整理；
  - 助理工作区只读；
  - 会话由 Dispatch 任务单一写入，桌面端在助理名下展示并标明来源。
- 会话保留天数沿用 F002-09，到期清理。
- 执行器随安装包一起分发：dmg 等桌面安装包内带 `openbitfun` CLI，桌面端优先使用安装包内的版本，修复 B004。缺失时，共享入口显示不可用并给出原因。

### D10 助理之间相互调用

- 主人的每个助理，以及别人共享给主人的每个助理，都以「助理」类目出现在可调用的子智能体列表中，显示助理名与来源。助理通过后台委派调用它们，不被阻塞，结果经 `AgentWait` 收回。
- **调用自己的助理**：在本机作为该助理名下的一个任务会话运行，标明来源「来自 助理 X」，按主人自己的任务处理，能力完整。
- **调用别人共享给我的助理**：与 D7 的对话是同一个授权和通道，在主人那边是一个标明来源的外部任务。
- **环检测**：每次调用携带调用链（参与过的助理及其所在设备的标识）。目标发现自己已在链中时明确拒绝，原因写明「循环调用」。这是结构性的环检测，不是按次数或字符串的限制。
- 外部任务能否继续调用别的助理，由 D8 的信任程度决定；调用的结果计入原任务的同时任务数与审计。
- 远程助理不可用（不在线、未授权、需要更新）时，列表中仍列出该助理并标明原因，不悄悄消失；调用时明确失败（修复 B003 类问题）。

### D11 远程场景

- **远程控制（手机端、IM）**：
  - 共享、发现、申请确认是桌面端局域网能力，手机端和 IM 不提供入口；
  - 主人不在桌面前时，确认框超时自动拒绝，使用者得到明确结果；
  - 运行中任务的权限审批照常经权限邮箱，手机端和 IM 可以处理。
- **Peer Device Mode**：共享、发现与共享助理的对话在对端模式下明确显示不支持，不回退到控制端本地数据。
- **远程工作区（SSH）**：外部任务在主人本机运行，不涉及远程工作区。
- **Detached Dispatch**：协议与已发布动词不变；局域网通道只是一种新的传输。
- **CLI 主机**：不提供共享与发现。

### D12 删除

AI协作仍在开发中、未发布，不保留兼容：

- **界面**：AI协作页与导航入口、创建与接受邀请、指纹核对、账号授权、按连接的信任与额度设置，全部删除。
- **桌面端与内核**：跨账号连接存储与连接 RPC、按连接的授权与信任文件、经中继列出远程助理与委派（同账号与跨账号），以及智能体列表中「最近 5 个任务」的接回入口，全部删除。接回改为在共享助理的对话列表中继续（D7）。
- **中继**：连接邀请、跨账号路由与 `cross_account_routing_v1` 能力删除。
- 有用的部分迁移进新流程，不保留旧格式：
  - 外部任务以助理身份运行、不改写助理；
  - 受阻时如实告知、排队；
  - 会话保留期限；
  - 外部任务会话在助理名下展示。

## 交互设计要点

- **入口**：
  - 「发现」按钮放在「创建助理」左边；
  - 「共享」按钮放在每张卡片的操作区（与查看、置顶、删除并列）；
  - 主助理同样可以共享。
- **状态**：
  - 共享中的卡片显示一个小角标；
  - 来自别人的助理在卡片上标来源，不在线时置灰。
  - 页面不出现「连接」「授权」「信任级别」「中继」等词；信任程度只在共享设置里出现一次，用一句话说明区别。
- **申请与确认**：
  - 使用者与主人看到的倒计时同步，以主人端为准，申请里带截止时间；
  - 结果以轻提示出现，不需要再点确认。
- **出错**：
  - 每种失败（不在线、本地网络权限被拒绝、需要更新、已撤销、对方拒绝、超时）都有一句话原因，以及可执行的下一步（重试、打开系统设置、更新）。

## 分阶段交付

每个阶段单独制定开发计划，均需审批：

1. **F002-10 基础**：设备共享身份、Bonjour 发现、加密的局域网通道与能力协商、安装包内带执行器（B004），以及第 5 版跨账号与中继能力的删除。
2. **F002-11 共享与申请**：共享设置与「共享中」管理、发现面板、申请与倒计时确认框、结果推送、撤销与移除。
3. **F002-12 使用共享的助理**：使用者列表中的共享助理、与它的直接对话与对话列表、审批与排队状态、离线展示。
4. **F002-13 助理之间相互调用**：「助理」类目的子智能体、本机助理任务会话、调用链环检测、不可用时如实列出。

## 已考虑的替代方案

1. **保留第 5 版：中继 + 账号连接 + AI协作页**：可以跨网络，但步骤多、入口分散，真机测试中多处静默失败。主人决定只做局域网，删除。
2. **经中继发现、只在自建中继上打开**：仍依赖登录与中继连接，确认推送受中继延迟与连接状态影响。未采用。
3. **只靠扫描网段或手输 IP**：需要用户知道地址，不符合「像 macOS 共享一样」。未采用；Bonjour 不可用时只给出原因。
4. **使用系统 Bonjour 服务（macOS dns-sd、Windows DNS-SD API）**：各平台各写一套，Linux 依赖 Avahi。未采用；用纯 Rust 实现，统一行为。
5. **保留邀请码与指纹核对**：局域网内由主人当场确认，加上确认框里的指纹短码，已能满足需要，与隔空投送一致。未采用。
6. **使用者只能经自己的助理调用共享助理（第 5 版）**：主入口太深。改为在列表中直接对话；经助理调用作为 D10 的补充。
7. **按使用者分别设置信任程度**：管理成本高。按共享的助理设置一次，需要不同程度时可以共享不同的助理。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 同一局域网里的陌生设备刷申请、打扰主人 | 默认不共享；没有共享时不广播；每个设备同一助理只能有一个申请；被拒绝后 1 分钟冷却；可以「拒绝并不再提示」 |
| 公共网络（咖啡店、酒店）里暴露共享的助理 | 主人每次申请都要当场确认；广播内容最少；后续可以按网络限制（只在指定 Wi-Fi 上共享），首期在共享设置中提示 |
| 冒充他人设备 | 授权绑定设备共享公钥；确认框显示指纹短码；公钥变化后授权失效 |
| 局域网内被窃听 | 端到端加密，域标签独立 |
| 系统本地网络权限或防火墙阻断发现 | 声明 Info.plist 键；被拒绝时说明原因并给出系统设置入口；Windows 防火墙提示在首次共享时说明 |
| 对方通过提问让助理泄露主人信息，或越权操作 | 普通程度的工具层限制；记忆与 `USER.md` 不进提示、读取须审批；完全信任须确认；审计；随时撤销 |
| 外部任务改变助理之后的行为 | 不参与记忆整理；助理工作区只读；会话标明来源 |
| 助理之间循环调用 | 调用链环检测，命中即拒绝并说明 |
| 外部智能体消耗主人的额度或违反条款 | 共享时提示并确认；凭据不出设备 |
| 资源滥用 | 同时任务数；排队；审计；撤销 |
| 局域网连接中断导致对话丢失 | 主人端会话为准；使用者按游标补收；提交幂等 |
| 删除中继跨账号后，已有的开发版数据残留 | 开发中功能，不保留兼容；删除时清理连接、授权、信任文件 |

## 兼容性、安全与回滚

- **协议**：Detached Dispatch 已发布的动词语义不变。局域网通道有独立的协议版本与能力声明，不兼容的设备显示为需要更新。
- **未发布功能**：第 5 版的 AI协作（连接、邀请、授权、信任、中继跨账号路由）尚未发布，不做迁移，直接删除，并清理本地残留文件。
- **安全**：本 RFC 的安全模型是「局域网 + 主人当场确认 + 首次信任的设备密钥」。它不防御主人在确认框中允许了冒充的设备，确认框的指纹短码用于降低这个风险。
- **回滚**：停止共享即停止广播并撤销所有授权；关闭共享能力即停止监听。

## 依赖

- F001：子智能体寻址、后台委派生命周期、外部智能体执行。
- 新增依赖：纯 Rust 的 mDNS/DNS-SD 实现（例如 `mdns-sd`），许可证与维护状况在 F002-10 计划中核对。

## 批准条件（可观察）

1. 两台未登录账号的 Mac 在同一局域网：A 在「助理」页共享助理 X 后，卡片显示「共享中」；B 点「发现」，60 秒内看到「A 的设备 · X」，悬停显示说明。
2. B 点击 X 申请：A 立即弹出确认框，允许按钮倒数 60 秒。不操作时到 0 自动拒绝，B 显示「未获同意」。再次申请后 A 点允许，B 在 2 秒内看到 X 进入自己的助理列表，标明来源。
3. B 点开 X 对话：回答体现 X 的人设，追问延续同一会话；A 在 X 名下看到这个标明来源的会话，可以查看，需要时审批；B 的对话里显示「等待 A 审批」。
4. B 关闭应用再打开，回到旧对话可以继续；A 设置的保留天数到期后，该会话被清理，B 继续时明确失败。
5. 普通程度下，B 的任务及其子智能体无法读取 A 的其他会话、控制 A 的桌面、创建定时任务、发布内容或调用 A 的其他助理；提示中没有记忆与 `USER.md`。A 改为完全信任并确认后，这些操作可用。
6. A 撤销 B 或停止共享后，B 的进行中任务被取消，X 在 B 的列表中标为「已撤销」，不能再发送；B 移除 X 后，A 的使用者列表中不再有 B。
7. A 不在线、A 拒绝本地网络权限、版本不兼容、超出同时任务数时，B 都看到一句话原因；超出同时任务数时排队。
8. A 自己有助理 X、Y，以及 B 共享给 A 的助理 Z：在 X 的对话中让它调用 Y 和 Z，都能后台完成并收回结果；Y 的任务会话在 Y 名下标明「来自 助理 X」。构造 X→Y→X 的调用时被拒绝，原因是循环调用。
9. 只安装 dmg（不另装 CLI）的设备可以处理别人的外部任务。
10. AI协作页、邀请、账号授权、中继跨账号路由都已删除；不登录账号时上述流程全部可用。
