# F002 RFC：AI协作——在局域网内共享助理

## 摘要

主人在「助理」页把自己的某个助理设为共享，设置信任程度、会话保留天数和同时处理的任务数。同一局域网里的其他 OpenBitFun 用户点「发现」，可以看到局域网内共享的助理（设备名 + 助理名），点击后申请使用。主人这边立即弹出确认框，确定按钮带倒计时，超时自动拒绝；主人确定后，使用者马上收到结果，这个助理进入使用者的助理列表，标明来源。使用者点开它直接对话。助理是多租户的：主人自己用的是助理的默认工作空间；每台使用者设备在该助理名下有自己的工作空间，这台设备的对话都保存在这个工作空间里。

整个过程只在局域网内：用 Bonjour（mDNS/DNS-SD）发现，不在同一网段时按局域网地址添加；设备之间直接连接并端到端加密，不经过中继，不需要登录账号。任务的执行、会话、事件和审批仍复用 Detached Dispatch。

此外，助理之间可以相互调用：主人自己的助理，以及别人共享给主人的助理，都能被主人的其他助理当作子智能体调用。

第 6 版用这套流程替换第 5 版的「中继 + 账号连接 + AI协作页」方案，相关界面与中继跨账号能力一并删除。

第 7 版（2026-11-03，主人修改需求）：同一局域网里的不同网段之间 Bonjour 互相看不到（组播不跨路由器），而公司网络常按楼层或部门分网段。因此在 Bonjour 发现之外，增加「按地址添加」：使用者在「发现」里输入对方的局域网地址，核对设备码后添加，之后像 Bonjour 发现的设备一样申请与使用；添加过的设备记住地址并自动重连（基准第 3 条、目标 10、D13、批准条件 11）。仍只限私有地址，不经中继，不走互联网。

第 6 版修订（2026-11-02，主人修改需求）：助理改为多租户——每台使用者设备在助理名下有自己的工作空间，继承助理的身份与人设，用户画像是使用者自己的，保留会话历史，暂不做租户记忆（基准第 4 条、D8、D9、非目标）；F002 上线前不考虑任何兼容，按最干净的方式实现（兼容性一节）。

## AI协作需求（基准，第 6 版）

本节是 F002 设计、实现与评审的基准。后续决策不得偏离这里，除非主人修改需求；不服务于这里的功能不保留。

1. **核心是「我的助理」**：只共享助理。助理有身份、有记忆、有工具。
2. **共享在助理上完成**：在「助理」页点助理上的共享按钮，设置信任程度、会话保留天数、同时处理的任务数，确定后该助理标为「共享中」。
3. **只在局域网内，不需要登录**：同一局域网的人点「发现」，看到共享的助理并申请使用；不在同一网段、发现不到时，可以输入对方的局域网地址添加。主人当场确认，确认框带倒计时，超时自动取消。结果直接经局域网推送，不经过中继。
4. **授权后像自己的助理一样用**：被授权的助理进入使用者的助理列表，标明来源，点开直接对话。助理是多租户的：默认工作空间属于主人；每台使用者设备第一次使用时，在该助理名下创建这台设备的工作空间，它的对话都作为会话保存在这里，标明来源；主人可以查看过程，需要时审批。
5. **处理外部任务时能力完整**：可以使用工具、创建子智能体、调用外部智能体（如 Claude Code）。
6. **助理之间可以相互调用**：自己的助理和别人共享给我的助理，都可以被我的其他助理调用。
7. **界面以助理为主**：主人看不懂、也用不上的内部模式名不出现在界面中。

## 背景与问题

- 第 5 版要求主人先在 AI协作页创建邀请、核对指纹、选择连接的信任级别，再把助理开放给连接；使用者还要在对话里让自己的助理去调用对方的助理。2026-11-02 在两台 Mac 上的真机测试中，这条路径没有走通：
  - 对方开放了什么在界面上看不到；
  - 连接、账号登录和中继连接任一环节出问题，助理都拿不到共享的助理，而且没有提示（缺陷 B001–B005）。
- 主人希望的形态和 macOS 的「共享」/隔空投送一样：同一局域网内直接发现，对方申请，自己当场同意。
- 现有可复用的能力：
  - Detached Dispatch：目标端持有任务、会话、事件日志与权限邮箱，按游标观察，支持幂等提交、取消、追加、继续与审批。
  - 外部任务以助理身份运行、不改写助理（F002-07）。
  - 受阻时如实告知、排队（F002-08）。
  - 会话保留期限（F002-09）。
  - 设备 X25519 + HKDF 消息密钥。
- 缺失的能力：
  - 局域网发现。仓库里没有 mDNS 依赖；现有的「局域网模式」是手机配对用的本机中继，不发现其他设备。
  - 设备之间的直接通道。
  - 与账号无关的设备身份。
  - 桌面安装包缺少任务执行器：执行器是 `openbitfun` CLI，dmg 中没有（B004）。

## 目标

1. 主人在「助理」页共享或停止共享任意一个自己的助理，并在共享时设置信任程度、会话保留天数和同时处理的任务数；共享中的助理有明确标记。
2. 同一局域网的使用者点「发现」，看到可用的共享助理（设备名 + 助理名）；悬停可以查看详情；点击后申请使用。
3. 主人立即收到确认框，确定按钮带倒计时，超时自动拒绝；确定或拒绝的结果立即推送给使用者。
4. 被授权的助理出现在使用者的助理列表中，标明「来自 某某的设备」；使用者点开直接对话，可以有多个对话，对话可以随时继续。
5. 每个对话在主人那边是该助理名下标明来源的独立会话；主人可以查看与审批；助理能力完整，信任程度决定它能碰到主人的哪些东西；外部任务不改写这个助理。
6. 主人能看到谁在用自己共享的助理，并逐个撤销；使用者能把共享助理从自己的列表中移除。
7. 不登录账号也能完成共享、发现、申请、使用的全过程。
8. 助理之间可以相互调用，包括主人自己的助理和别人共享给主人的助理；调用形成环时明确拒绝。
9. 对方不在线、不在同一局域网、版本不兼容、授权已撤销、超出同时任务数时，界面与助理都明确说明原因。
10. 同一局域网的不同网段之间，使用者输入主人设备的地址即可添加该设备，之后申请、对话、在线状态与推送与 Bonjour 发现的设备一致。

## 非目标

- 跨局域网（经中继或互联网）共享助理；第 5 版的中继跨账号连接一并删除。「按地址添加」只接受私有地址（D13），不是跨互联网的入口。
- 自动扫描其他网段寻找共享设备。
- 公开的助理市场，或按账号检索他人的助理。
- 同一账号的设备经中继互相调用助理（F002-02）。本机与同一局域网的自己的设备，按本流程共享即可。
- 委派编码任务、把改动以分支带回（第 4 版已删除）。
- 租户的记忆（从租户自己的会话自动整理记忆）。本版不做，租户只有会话历史与自己的 `USER.md`；以后单独立项。
- 共享智能体模式或外部智能体本身（第 4 版已删除）。
- 计费结算、按助理隔离的记忆。
- 在手机端、IM 或 CLI 主机上共享或发现助理。

## 决策

### D1 局域网发现：Bonjour

- 共享了至少一个助理的桌面端，在局域网内广播服务 `_openbitfun._tcp`。广播内容只有：
  - 设备名；
  - 主人的显示名（取本机用户名，可修改）；
  - 设备共享公钥（连接时按完整公钥校验；指纹短码只用于界面显示，由公钥派生，不用于校验）；
  - 通道端口；
  - 协议版本。
- 共享助理的名称和说明不放进广播，由对方连上通道后读取。
- 没有共享任何助理时不广播。
- 使用者打开「发现」面板时浏览；有可用的来自共享的助理时也在后台浏览，但后台只连接这些助理的主人，用于在线状态与推送，不读取其他设备的目录。
- Bonjour 组播只在一个网段内传播。不同网段之间靠 D13「按地址添加」，不依赖网管配置 mDNS 反射；网络已配置反射时，Bonjour 也能跨网段发现，两者并存。
- 使用纯 Rust 的 mDNS 实现，归属 services 层，由桌面端适配层启动，不依赖操作系统的 Bonjour 服务。
- macOS 15 及以上需要在 Info.plist 声明本地网络用途与 Bonjour 服务类型；首次使用时系统会请求「本地网络」权限。被拒绝时，「发现」面板说明原因，并给出打开系统设置的入口。

### D2 设备共享身份：与账号无关

- 每台设备生成一对持久的共享身份密钥（X25519），与账号和中继无关，不登录也存在。
- 显示名默认取本机用户名，可以在「发现」面板中修改。
- 授权绑定到使用者设备的共享公钥：申请时双方交换公钥，主人确定后固定下来，与隔空投送一样首次信任。之后对方公钥变化，原授权失效，需要重新申请。

### D3 局域网通道

- 设备之间建立直接连接（WebSocket over TCP）。端口只监听私有地址网段的网卡，不监听公网地址与回环以外的接口。
- 通道优先使用一个固定的默认端口，让对方只凭地址就能连上；默认端口被占用时改用随机端口，这时本机显示的地址带上端口（D13）。具体端口号在开发计划中确定。
- 消息用双方共享密钥派生的消息密钥加密，复用现有的设备消息密钥派生方式，但使用独立的域标签。
- 申请与确认、确认结果推送、任务提交与进度观察、审批，都走这条通道。
- 握手中协商协议版本与能力。版本号相同不能代替能力声明；不兼容时，「发现」面板把该设备显示为「需要更新」。
- 未授权的设备只能读取共享助理的名称与说明，以及发出申请，不能提交任务。

### D4 共享助理（主人）

- 「助理」页的每张卡片增加「共享」按钮。点击后弹出共享设置：
  - **信任程度**：普通 / 完全信任，含义见 D8；
  - **会话保留天数**：1、7、30、90，默认 7；
  - **同时处理的任务数**：默认 2。
- 确定后卡片标「共享中 · N 人在用」。点击标记打开管理视图：修改设置，查看使用者（显示名 + 设备名 + 授权时间 + 最近使用），逐个撤销或删除该使用者的数据，或停止共享。
- 设置改的是该助理的共享，对所有使用者生效：
  - 信任程度从下一回合起生效；
  - 保留天数对已有会话同样生效。
- 停止共享会撤销全部授权。
- 外部智能体可能消耗主人在服务商处的额度。助理配置了外部智能体时，共享设置中提示额度与条款（例如 Claude Code 订阅登录用于他人请求可能超出订阅限定，建议改用 API Key），由主人确认一次。凭据绝不出设备。

### D5 发现与申请（使用者）

- 「助理」页标题栏的「创建助理」左边增加「发现」按钮，打开发现面板：
  - 按设备分组，显示局域网内的共享助理（设备名 + 助理头像与名称）；
  - 悬停显示详情：说明、主人显示名、设备名；
  - 每个助理显示状态：可申请 / 申请中（倒计时）/ 已在你的列表中 / 需要更新。
  - 面板为空时说明原因：没有发现共享的助理，或本地网络权限被拒绝。
- 点击「可申请」的助理即发出申请，使用者看到「等待 某某 确认」和剩余秒数。主人确定后，提示「已添加」，发现面板自动关闭，回到「助理」页并显示「来自共享」中的这个助理（2026-11-03 主人要求）；被拒绝或超时，提示「未获同意」，面板保持打开。
- 防打扰：同一设备对同一助理同一时间只能有一个申请；被拒绝或超时后 1 分钟内不能再次申请。主人可以在确认框中选择「拒绝并不再提示」，屏蔽这台设备。

### D6 确认框（主人）

- 收到申请时，主人的桌面端立即弹出模态确认框，内容为「某某（设备名）想使用你的助理『X』」，并显示申请设备的公钥指纹短码。
- 按钮为「拒绝」和「允许（60）」，允许按钮上的数字逐秒倒数，到 0 自动拒绝。
- 应用不在前台时同时发系统通知，点通知打开确认框。
- 多个申请依次排队，每个独立计时。
- 申请时主人设备不可达的，使用者立即收到「对方不在线」，不排队、不重试。

### D7 使用共享的助理（使用者）

- 被授权的助理出现在使用者「你的助理」列表中，卡片标「来自 某某的设备」，对方不在线时置灰并显示「不在线」。
- 点开即进入与它的对话界面，和与自己助理对话一致：
  - 每个对话是一个外部任务，追问延续同一会话；
  - 对话列表在该助理下面，可以随时回到旧对话继续，直到超过主人设置的保留天数；
  - 需要主人审批时，对话里显示「等待 某某 审批」；
  - 超出同时任务数时排队，并显示排队状态。
- 使用者可以把它从列表中移除，这会撤销该授权、删除使用者本地的对话记录，并让主人那边删除这台设备的租户工作空间（D9）。
- 使用者本地的对话记录只是展示副本，以主人那边的会话为准，按游标补收。离线时可以查看已收到的内容，不能发送。

### D8 信任程度（沿用第 5 版 D9 的含义，改为按共享的助理设置）

- **普通（默认）**：助理可以使用工具、创建子智能体、调用外部智能体，但目标端在工具层禁止以下操作，不依赖提示词：
  - 读取或操作本机其他会话与工作区（这台设备自己租户工作空间里的会话除外，见 D9）；
  - 控制主人的桌面、浏览器或终端会话；
  - 创建定时任务或持久目标、发布对外内容、操作 OpenBitFun 自身；
  - 调用主人的其他助理。

  主人的记忆摘要与主人的 `USER.md` 不放进提示；文件工具读取它们须主人审批。提示中的用户画像是租户自己的 `USER.md`（D9）。命令执行与外部智能体按审批策略处理，界面如实说明这层保护依靠审批。
- **完全信任**：开启前显示风险并需要主人确认。开启后外部任务与主人自己的任务权限相同，包括调用主人的其他助理。
- 两种程度下，审批人、同时任务数、审计、撤销都不变。委派内容一律作为不可信输入处理。

### D9 执行与外部任务（沿用）

- 执行复用 Detached Dispatch：
  - 外部任务固定使用 `remote` 审批策略；
  - 权限请求进入主人的权限邮箱，桌面端、手机端、IM 都能审批；
  - `AskUserQuestion` 明确失败，不等待。
- **多租户工作空间**：
  - 助理的默认工作空间属于主人，主人自己的对话与调用都在这里。
  - 每台使用者设备是一个租户，以设备共享公钥（派生的设备 id）区分。该设备第一次提交任务时，执行器在该助理名下创建这台设备的工作空间；之后这台设备的所有对话都是这个工作空间里的会话，文件也留在这里，可以跨对话延续。
  - 租户之间互相看不到；租户看不到主人的默认工作空间，只按 D8 读取助理的人设与说明。
  - 租户工作空间放在产品数据目录下，不放在助理工作区里，主人的助理在默认工作空间中看不到租户的文件。
- **身份、人设与用户画像**：
  - 助理的身份与人设（`IDENTITY.md`、`SOUL.md` 等）从助理工作区继承，只读，主人修改后对所有租户的下一回合生效；租户工作空间不运行首次引导（`BOOTSTRAP.md`）。
  - 用户画像不继承：每个租户工作空间有自己的 `USER.md`，描述的是这台设备的使用者，创建时只填入使用者的显示名与设备名，之后由助理在该租户的对话中按通常方式补充。它不进入主人的画像，也不给其他租户看到；两种信任程度下都如此。
- **会话历史**：
  - 每个对话的完整历史保存在租户工作空间（以主人那边为准，使用者端是展示副本），保留期内回到旧对话继续时上下文完整。
  - 在新对话中，助理可以按需查看这台设备之前的对话：会话列表与会话历史工具对外部任务开放，但只作用于本租户工作空间里的会话；不自动注入提示。
  - 记忆（跨对话的自动整理）暂不做，见非目标。
- 外部任务以该助理的人设运行，不改写助理：
  - 不参与记忆整理（主人的记忆与租户的会话都不互相写入）；
  - 助理工作区只读；
  - 会话由 Dispatch 任务单一写入，桌面端在助理名下按租户分组展示，标明来源。
- 会话保留天数沿用 F002-09，到期清理会话；租户工作空间在授权已不存在且没有会话时删除。
- 使用者移除共享的助理时，主人那边删除这台设备的租户工作空间（会话与文件），审计记录保留。主人撤销授权或停止共享时，租户工作空间保留到会话按保留天数到期；管理视图提供「删除该使用者的数据」立即删除。
- 执行器随安装包一起分发：dmg 等桌面安装包内带 `openbitfun` CLI，桌面端优先使用安装包内的版本，修复 B004。缺失时，共享入口显示不可用并给出原因。

### D10 助理之间相互调用

- 主人的每个助理，以及别人共享给主人的每个助理，都以「助理」类目出现在可调用的子智能体列表中，显示助理名与来源。助理通过后台委派调用它们，不被阻塞，结果经 `AgentWait` 收回。
- **调用自己的助理**：在本机作为该助理名下的一个任务会话运行，标明来源「来自 助理 X」。调用发生在主人自己的会话中时，会话放在被调用助理的默认工作空间，按主人自己的任务处理，能力完整；调用发生在某个租户的外部任务中（仅完全信任）时，会话放在被调用助理名下同一租户的工作空间，仍是该租户的任务。
- **调用别人共享给我的助理**：与 D7 的对话是同一个授权和通道，在主人那边是一个标明来源的外部任务。
- **环检测**：每次调用携带调用链（参与过的助理及其所在设备的标识）。目标发现自己已在链中时明确拒绝，原因写明「循环调用」。这是结构性的环检测，不是按次数或字符串的限制。
- 外部任务能否继续调用别的助理，由 D8 的信任程度决定；调用的结果计入原任务的同时任务数与审计。
- 远程助理不可用（不在线、未授权、需要更新）时，列表中仍列出该助理并标明原因，不悄悄消失；调用时明确失败（修复 B003 类问题）。

### D11 远程场景

- **远程控制（手机端、IM）**：
  - 共享、发现、申请确认是桌面端局域网能力，手机端和 IM 不提供入口；
  - 主人不在桌面前时，确认框超时自动拒绝，使用者得到明确结果；
  - 运行中任务的权限审批照常经权限邮箱，手机端和 IM 可以处理。
- **Peer Device Mode**：共享、发现与共享助理的对话在对端模式下明确显示不支持，不回退到控制端本地数据。
- **远程工作区（SSH）**：外部任务在主人本机运行，不涉及远程工作区。
- **Detached Dispatch**：协议与已发布动词不变；局域网通道只是一种新的传输。
- **CLI 主机**：不提供共享与发现。

### D12 删除

AI协作仍在开发中、未发布，不保留兼容：

- **界面**：AI协作页与导航入口、创建与接受邀请、指纹核对、账号授权、按连接的信任与额度设置，全部删除。
- **桌面端与内核**：跨账号连接存储与连接 RPC、按连接的授权与信任文件、经中继列出远程助理与委派（同账号与跨账号），以及智能体列表中「最近 5 个任务」的接回入口，全部删除。接回改为在共享助理的对话列表中继续（D7）。
- **中继**：连接邀请、跨账号路由与 `cross_account_routing_v1` 能力删除。
- 有用的部分迁移进新流程，不保留旧格式：
  - 外部任务以助理身份运行、不改写助理；
  - 受阻时如实告知、排队；
  - 会话保留期限；
  - 外部任务会话在助理名下展示。

### D13 按地址添加（不同网段）

- **主人一侧**：共享管理视图和「发现」面板底部显示本机的局域网地址（每个私有地址一行，例如有线与 Wi-Fi；默认端口被占用时带端口）与本机设备码，并说明「其他网段的设备可以在『发现』中输入这个地址」。
- **使用者一侧**：
  - 「发现」面板提供「按地址添加」，输入地址（可带端口）后连接。
  - 只接受私有地址（IPv4 的 10/8、172.16/12、192.168/16 与链路本地地址，IPv6 的 ULA 与链路本地地址）；公网地址、域名与回环地址直接拒绝并说明。
  - 连上后显示对方的设备名、显示名与设备码，提示「请核对对方屏幕上显示的设备码」；使用者确认后，该设备加入「发现」列表并标「按地址添加」，之后的申请、确认框、倒计时与结果推送与 D5、D6 相同。
- **身份**：首次连接时没有广播里的公钥可比对，按首次信任处理，由使用者核对设备码防冒充；确认后固定该设备的公钥。之后公钥变化时拒绝连接，并显示「对方设备的身份已变化」，需要移除后重新添加。主人的确认框照常显示申请设备的设备码。
- **记住与重连**：
  - 按地址添加的设备保存在使用者本机（地址、公钥、名称），「发现」面板中可以移除。
  - 打开「发现」时读取它们的目录；有来自它们的可用助理时，在后台定时用记住的地址重连，用于在线状态与推送，与 Bonjour 发现的设备一致。
  - 对方地址变化（例如 DHCP 重新分配）且 Bonjour 也看不到时，显示「不在线」，使用者可以修改地址；同一公钥的设备若被 Bonjour 发现，自动更新地址。
- **出错**：地址格式不对、不是私有地址、连接不上（并提示检查代理、VPN 或防火墙）、对方没有共享任何助理、版本不兼容、身份变化，各有一句原因。
- **远程场景**：与 D11 一致，只在桌面端提供；Peer Device Mode 下不可用；手机端、IM、CLI 主机不提供入口。

## 交互设计要点

- **入口**：
  - 「发现」按钮放在「创建助理」左边；
  - 「共享」按钮放在每张卡片的操作区（与查看、置顶、删除并列）；
  - 主助理同样可以共享。
- **状态**：
  - 共享中的卡片显示一个小角标；
  - 来自别人的助理在卡片上标来源，不在线时置灰。
  - 页面不出现「连接」「授权」「信任级别」「中继」等词；信任程度只在共享设置里出现一次，用一句话说明区别。
- **按地址添加**：
  - 「按地址添加」放在「发现」面板底部，平时是一行入口，点开才显示地址输入框，不打扰同一网段里的正常发现；
  - 本机地址与设备码显示在「发现」面板底部和共享管理视图中，可以复制；
  - 设备码核对是一个明确的确认步骤，不是自动通过。
- **申请与确认**：
  - 使用者与主人看到的倒计时同步，以主人端为准，申请里带截止时间；
  - 结果以轻提示出现，不需要再点确认。
- **出错**：
  - 每种失败（不在线、本地网络权限被拒绝、需要更新、已撤销、对方拒绝、超时）都有一句话原因，以及可执行的下一步（重试、打开系统设置、更新）。

## 分阶段交付

每个阶段单独制定开发计划，均需审批：

1. **F002-10 基础**：设备共享身份、Bonjour 发现、加密的局域网通道与能力协商、安装包内带执行器（B004）。
2. **F002-11 共享与申请**：共享设置与「共享中」管理、发现面板、申请与倒计时确认框、结果推送、撤销与移除；目标端的授权改为按设备共享公钥，同时删除第 5 版跨账号与中继能力（D12）。
3. **F002-12 使用共享的助理**：使用者列表中的共享助理、与它的直接对话与对话列表、审批与排队状态、离线展示。
4. **F002-13 助理之间相互调用**：「助理」类目的子智能体、本机助理任务会话、调用链环检测、不可用时如实列出。
5. **F002-14 按地址添加**：通道固定默认端口、本机地址与设备码展示、按地址添加与设备码核对、记住的设备与后台重连、各类出错说明（D13）。不依赖 F002-12/13，可以在 F002-11 之后任意时间交付。

## 已考虑的替代方案

1. **保留第 5 版：中继 + 账号连接 + AI协作页**：可以跨网络，但步骤多、入口分散，真机测试中多处静默失败。主人决定只做局域网，删除。
2. **经中继发现、只在自建中继上打开**：仍依赖登录与中继连接，确认推送受中继延迟与连接状态影响。未采用。
3. **只靠扫描网段或手输 IP**：需要用户知道地址，不符合「像 macOS 共享一样」。第 6 版未采用；第 7 版改为以 Bonjour 为主、手输地址为补充（D13），与 macOS 访达「连接服务器」一致。自动扫描其他网段仍不采用：流量大，容易被安全软件当作探测，而且网段之间可能有防火墙，结果不可靠。
8. **要求网管在路由器上开启 mDNS 反射**：不改产品即可跨网段发现，但多数用户无法改网络配置。作为可选的网络方案保留（D1），产品不依赖它。
9. **自建跨网段的发现服务或中继**：需要一台常驻的服务和配置，与「不需要登录、不经中继」相悖。未采用。
4. **使用系统 Bonjour 服务（macOS dns-sd、Windows DNS-SD API）**：各平台各写一套，Linux 依赖 Avahi。未采用；用纯 Rust 实现，统一行为。
5. **保留邀请码与指纹核对**：局域网内由主人当场确认，加上确认框里的指纹短码，已能满足需要，与隔空投送一致。未采用。
6. **使用者只能经自己的助理调用共享助理（第 5 版）**：主入口太深。改为在列表中直接对话；经助理调用作为 D10 的补充。
7. **按使用者分别设置信任程度**：管理成本高。按共享的助理设置一次，需要不同程度时可以共享不同的助理。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 同一局域网里的陌生设备刷申请、打扰主人 | 默认不共享；没有共享时不广播；每个设备同一助理只能有一个申请；被拒绝后 1 分钟冷却；可以「拒绝并不再提示」 |
| 公共网络（咖啡店、酒店）里暴露共享的助理 | 主人每次申请都要当场确认；广播内容最少；后续可以按网络限制（只在指定 Wi-Fi 上共享），首期在共享设置中提示 |
| 冒充他人设备 | 授权绑定设备共享公钥；确认框显示指纹短码；公钥变化后授权失效 |
| 局域网内被窃听 | 端到端加密，域标签独立 |
| 系统本地网络权限或防火墙阻断发现 | 声明 Info.plist 键；被拒绝时说明原因并给出系统设置入口；Windows 防火墙提示在首次共享时说明 |
| 对方通过提问让助理泄露主人信息，或越权操作 | 普通程度的工具层限制；记忆与 `USER.md` 不进提示、读取须审批；完全信任须确认；审计；随时撤销 |
| 外部任务改变助理之后的行为 | 不参与记忆整理；助理工作区只读；会话标明来源 |
| 助理之间循环调用 | 调用链环检测，命中即拒绝并说明 |
| 外部智能体消耗主人的额度或违反条款 | 共享时提示并确认；凭据不出设备 |
| 资源滥用 | 同时任务数；排队；审计；撤销 |
| 按地址添加时连到冒充的设备 | 只接受私有地址；连接后展示设备码，由使用者核对后才添加；固定公钥，变化即拒绝；主人仍须当场确认每个申请 |
| 输入的地址被用来探测内网其他主机 | 只在使用者自己的设备上、由使用者手动发起；只连接一个地址与端口，不扫描；只接受私有地址；非 OpenBitFun 的服务在握手阶段失败，只返回「无法连接」 |
| 代理或 VPN 的 TUN 模式接管了到其他网段的路由，连接走代理失败 | 出错时说明「可能被代理、VPN 或防火墙拦截」；2026-11-03 测试环境中，本机到 172.17.9.0/24 的路由就经过代理的 TUN 网卡 |
| 默认端口被占用或被防火墙拦截 | 占用时改用随机端口并在本机地址中显示端口；Windows 首次共享时提示放行 |
| 局域网连接中断导致对话丢失 | 主人端会话为准；使用者按游标补收；提交幂等 |
| 删除中继跨账号后，已有的开发版数据残留 | F002 上线前不考虑兼容：不迁移，也不写清理旧文件的代码，按最干净的方式实现 |
| 租户之间或租户与主人之间的数据混用 | 租户工作空间按设备公钥区分并放在助理工作区之外；执行器在准入时决定工作空间，不接受调用方提供的路径 |

## 兼容性、安全与回滚

- **协议**：Detached Dispatch 已发布的动词语义不变。局域网通道有独立的协议版本与能力声明，不兼容的设备显示为需要更新。
- **未发布功能**：F002 上线前，F002 自己的数据格式、文件与协议都不考虑兼容。第 5 版的 AI协作（连接、邀请、授权、信任、中继跨账号路由）直接删除，不迁移，也不写清理旧文件的代码；F002 各阶段之间的格式变化同样不做兼容。已发布的 Detached Dispatch 与会话存储仍按 AGENTS.md 的升级兼容规则处理。
- **安全**：本 RFC 的安全模型是「局域网 + 主人当场确认 + 首次信任的设备密钥」。它不防御主人在确认框中允许了冒充的设备，确认框的指纹短码用于降低这个风险。
- **回滚**：停止共享即停止广播并撤销所有授权；关闭共享能力即停止监听。

## 依赖

- F001：子智能体寻址、后台委派生命周期、外部智能体执行。
- 新增依赖：纯 Rust 的 mDNS/DNS-SD 实现（例如 `mdns-sd`），许可证与维护状况在 F002-10 计划中核对。

## 批准条件（可观察）

1. 两台未登录账号的 Mac 在同一局域网：A 在「助理」页共享助理 X 后，卡片显示「共享中」；B 点「发现」，60 秒内看到「A 的设备 · X」，悬停显示说明。
2. B 点击 X 申请：A 立即弹出确认框，允许按钮倒数 60 秒。不操作时到 0 自动拒绝，B 显示「未获同意」。再次申请后 A 点允许，B 在 2 秒内看到 X 进入自己的助理列表，标明来源。
3. B 点开 X 对话：回答体现 X 的人设，追问延续同一会话；A 在 X 名下 B 的工作空间里看到这个标明来源的会话，可以查看，需要时审批；B 的第二个对话在同一工作空间里，能看到第一个对话留下的文件；B 的对话里显示「等待 A 审批」。
4. B 关闭应用再打开，回到旧对话可以继续；A 设置的保留天数到期后，该会话被清理，B 继续时明确失败。
5. 普通程度下，B 的任务及其子智能体无法读取 A 的其他会话、控制 A 的桌面、创建定时任务、发布内容或调用 A 的其他助理；提示中没有记忆与 `USER.md`。A 改为完全信任并确认后，这些操作可用。
6. A 撤销 B 或停止共享后，B 的进行中任务被取消，X 在 B 的列表中标为「已撤销」，不能再发送；B 移除 X 后，A 的使用者列表中不再有 B，X 名下 B 的工作空间被删除。
7. A 不在线、A 拒绝本地网络权限、版本不兼容、超出同时任务数时，B 都看到一句话原因；超出同时任务数时排队。
8. A 自己有助理 X、Y，以及 B 共享给 A 的助理 Z：在 X 的对话中让它调用 Y 和 Z，都能后台完成并收回结果；Y 的任务会话在 Y 名下标明「来自 助理 X」。构造 X→Y→X 的调用时被拒绝，原因是循环调用。
9. 只安装 dmg（不另装 CLI）的设备可以处理别人的外部任务。
10. AI协作页、邀请、账号授权、中继跨账号路由都已删除；不登录账号时上述流程全部可用。
11. 两台 Mac 在同一局域网的不同网段（Bonjour 互相看不到）：A 共享助理 X 后，在共享管理视图看到本机地址与设备码；B 在「发现」中按地址添加 A，核对设备码后看到 X 并申请，A 允许后 B 可以对话；A 撤销后 B 立即显示「已撤销」；A 退出后 B 显示「不在线」，A 重新打开后自动恢复；输入公网地址、错误地址、不可达地址或身份变化的设备时，B 都看到一句话原因。
