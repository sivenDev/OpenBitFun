# F002 RFC：AI协作——把助理开放给其他设备与账号

## 摘要

主人把自己的助理开放给信任的人：自己的其他设备，或已建立连接的其他账号。对方的 AI 或人通过委派把问题交给这个助理；每个外部任务是该助理名下的一个独立会话，助理以完整能力处理，结果异步回到对方。跨账号连接分「普通」与「完全信任」两个信任级别，决定外部任务能碰到主人的哪些东西。

发起方沿用 F001 的「智能体目录 + 异步委派」：被开放的助理以远程智能体出现在发起方的列表中，通过 `Task` 后台委派，用 `AgentWait` 取回结果。执行复用 Detached Dispatch：任务、会话、事件日志和权限邮箱都由目标端持有，按游标观察，支持幂等提交与能力协商。跨账号部分包括邀请与配对、连接级端到端密钥、relay 的跨账号路由授权、按连接授权、目标端审批与额度。

## AI协作需求（基准）

本节是 F002 设计、实现与评审的基准。后续决策不得偏离这里，除非主人修改需求；不服务于这里的功能不保留。

1. **核心是「我的助理」**：助理是有身份、有记忆、有工具的个人 AI。主人把它开放给信任的人，包括自己的其他设备和其他账号，对方的 AI 或人把问题交给它解决。开放的对象只有助理。
2. **每个外部任务是一个独立会话**：会话显示在该助理名下，标明来源；主人可以查看过程，并在需要时审批。
3. **助理处理外部任务时能力完整**：可以使用工具、创建子智能体、调用外部智能体（如 Claude Code），不能被削减成只会对话的助理。
4. **信任按连接决定**：主人核对指纹并接受连接，本身就是一次信任决定。主人只需要回答「这个连接我信任到什么程度」，不需要理解多套交叉的开关。
5. **界面以助理为主**：主人看不懂、也用不上的内部模式名不出现在界面中。

## 背景与问题

- Detached Dispatch 已经能把任务提交到另一台 OpenBitFun 主机：目标端持有任务、事件日志与权限邮箱，发起方可以断开，协议有 `probe`、`submit`、`status`、`cancel`、`append`、`continue`、`answer`。relay 不缓存任务；`AskUserQuestion` 不可用。
- 账号设备通道和 Peer Device Mode 都限定为同一账号：relay 在路由前校验账号成员关系，载荷用账号主密钥加密。另一个账号既拿不到这把密钥，也通不过成员校验。
- 助理目前只能由主人自己使用，没有「把助理交给别人用」的概念。
- 参考：OpenBot 的跨账号模式是「主机 + 成员」，用一次性邀请链接或二维码加入，撤销后结束该成员的所有会话，经 WebRTC 端到端连接。它在条款说明中把「其他人使用你主机上的 Claude」列为高风险用法。

**范围修正（第 4 版）**：第 3 版及之前的阶段已经交付了按智能体模式开放、按 ACP 外部智能体开放，以及委派编码任务（Git 交付）。它们把本机的模型、工具和凭据借给别人跑任务，不带身份和记忆，不服务于上面的基准，本版删除。调用外部智能体改为助理在处理外部任务时的能力（需求第 3 条）。

## 目标

1. 目标主人选择开放哪些助理，并逐个授权给自己的设备或已连接的账号；默认不开放、不授权。
2. 跨账号的双方需要先完成邀请与配对，任何一方都可以随时撤销。
3. 发起方的智能体列表中可以看到被授权的远程助理，标明所属账号、设备、在线状态和兼容性。
4. 发起方的助理可以把任务后台委派给远程助理，不被阻塞；结果回到发起会话。
5. 发起方离线或重启后，重新上线时能补收已完成的结果。
6. 外部任务在目标端是该助理名下的独立会话，主人可以查看与审批；助理能力完整，连接的信任级别决定它能碰到主人的哪些东西；外部任务不会改写这个助理。
7. 目标离线、版本不兼容、未授权、授权已撤销或超出额度时，委派明确失败并给出原因。

## 非目标

- 开放智能体模式或外部智能体本身（第 4 版删除）。
- 委派编码任务、把改动以分支带回发起方（第 4 版删除）。
- relay 侧的任务排队，或离线目标的存储转发。
- 任意多跳的互相委派。
- 公开的助理市场、按陌生人检索。
- 账号之间的计费结算。
- 按助理隔离的记忆。

## 决策

### D1 执行复用 Dispatch，信任与路由另建

远程委派是一次由智能体发起、指定了目标助理的 Detached Dispatch 任务。执行、幂等、游标观察、取消、追加与审批语义沿用 Dispatch。

目标端通过协商能力声明支持委派：`agent_delegation_v1`（目录查询与委派任务）、`cross_account_delegation_v1`（跨账号）、开放助理另需新的能力（暂定名 `assistant_delegation_v1`）。目标不声明相应能力时，不展示，也不能被委派。版本号相同不能代替能力声明。

### D2 两种关系：同账号与跨账号连接

- **同账号**：沿用现有账号设备通道和账号主密钥，无需配对。
- **跨账号**：引入「连接」这一持久关系。
  - **建立**：一方生成一次性、有过期时间的邀请（链接或二维码），另一方查看邀请内容后接受。
  - **身份**：每台设备有自己的设备身份密钥对，配对时交换并固定对方的公钥，接受邀请前展示指纹供核对。
  - **加密**：跨账号载荷用连接级密钥端到端加密，账号主密钥绝不离开本账号。
  - **撤销**：任一方都能撤销连接，撤销后对方新的委派立即被拒绝，进行中的任务按 D6 处理。

### D3 relay 跨账号路由授权

relay 只在存在有效连接记录的两个设备之间路由委派相关的 RPC。relay 只校验连接与身份，只看到密文，不存储委派内容。

relay 是独立部署的服务，可能与客户端版本不一致：客户端要先确认 relay 声明了跨账号路由能力，才展示跨账号入口；relay 不支持时，入口显示为不可用，并给出原因。

### D4 开放助理与授权

- **开放对象**：开放项只能是本机的一个助理（助理工作区，带人设文件 `SOUL.md`、`IDENTITY.md`、`USER.md`）。每个开放项包括展示名与说明（默认取助理名称）、审批策略（D6）与额度（D7）。
- **授权**：「开放项 × 设备或连接」的组合。同账号设备可以一次授权全部；跨账号逐项授权。目录查询只返回请求方被授权的助理，不暴露人设内容、记忆或路径。
- **外部智能体的额度提示**：助理处理外部任务时可能调用外部智能体，消耗主人在服务商处的额度。开放助理时按智能体显示额度与条款提示（例如 Claude Code 的订阅登录用于他人请求可能超出 Anthropic 对订阅「个人日常使用」的限定，建议改用 API Key），由主人确认一次。外部智能体只使用目标设备自己的凭据，凭据绝不跨设备、跨账号传输。
- **旧的开放记录**：第 3 版的模式与外部智能体开放记录保留在磁盘上、照常读取，但不再出现在目录中、不再接受委派；界面把它们标为「已不支持」，主人可以删除。发起方委派到这类条目时收到明确的「已不再开放」。

### D5 外部任务

- 每个外部任务是一个纯消息任务：输入是问题文本，结果是回答文本，外加有大小上限的附件。发起方不能指定目标机上的任何路径，也不传输代码仓库。
- 任务在目标端以该助理的人设运行，工作目录是该任务独立的目录。同一任务的追问延续同一会话。
- 旧版发起方提交的编码任务被明确拒绝，原因是「目标只接受消息任务」。

### D6 审批、交互与撤销

- 外部任务固定使用 Dispatch 的 `remote` 审批策略，权限请求进入目标端权限邮箱，审批人是目标主人。同账号时就是本人在当前驱动界面审批；跨账号时发起方只能看到「等待对方审批」，不能代替目标主人批准。目标主人可以为开放项设置更宽松的策略，比如只读操作自动通过。
- 审批经 Dispatch 权限邮箱完成，因此桌面端、手机端、IM 与命令行 `dispatch answer` 都可以处理。
- `AskUserQuestion` 沿用 Dispatch 现状：明确失败，不等待。
- 撤销连接或授权时，该连接上进行中的任务被取消；目标端会话保留在目标主人本地，发起方收到「授权已撤销」的结果。

### D7 额度与审计

- **额度**：每个开放项可以设置每个连接的并发任务数和单任务时长上限。子智能体与外部智能体的运行计入所属任务的时长。这是授权边界上的安全与资源控制，不属于智能体循环内的硬编码限制。
- **审计**：目标端记录每次跨账号委派的来源账号、设备、助理、开始与结束时间、结果状态、任务开始时连接的信任级别，以及任务调用了哪些外部智能体，主人可以查看。

### D8 发起与结果回收

`Task` 委派给远程助理时：

1. 发起方提交任务，立即返回后台任务标识。
2. 发起方持久化一条与发起会话和后台任务关联的出站记录，观察器按游标跟进。
3. 任务结束时，结果作为该后台任务的完成结果交给 `AgentWait`。
4. 发起方重启后，按出站记录重新挂接观察器并补收结果。

### D9 连接的信任级别

- 委派消息带上来源元数据：账号、设备、会话、智能体。目标端把委派内容当作不可信输入处理，不提升权限。
- 跨账号连接有两个信任级别，由目标主人为每个连接选择。接受连接只证明对方设备的身份；选择级别才是信任决定。同账号设备是主人自己的设备，按完全信任处理。
- **普通（默认）**：助理可以使用工具、创建子智能体、调用外部智能体，但目标端在工具层禁止以下操作，不依赖提示词：
  - 读取或操作本机的其他会话与工作区（会话历史、会话消息、会话控制、工作区列表一类工具）；
  - 控制主人的桌面、浏览器或终端会话（电脑操作、ControlHub 一类工具）；
  - 创建定时任务或持久目标，发布页面、外观或其他对外内容，操作 OpenBitFun 自身。

  记忆摘要与 `USER.md` 不放进提示；文件工具读取 `USER.md` 或记忆目录必须经主人审批，不受宽松审批策略影响。命令执行与外部智能体按审批策略处理：它们能读取本机当前用户可读的文件，所以普通级别对记忆的保护依靠审批，不是物理隔离。界面与确认提示必须如实说明这一点。
- **完全信任**：开启前显示风险（对方任务中夹带的第三方提示注入、对方账号或设备失窃、模型误用工具，以及记忆是整个产品共享的一份）并需要主人确认。开启后，该连接的任务与同账号一样：上述操作都可以使用，记忆摘要与 `USER.md` 放进提示。
- 两个级别下，审批人、额度、审计、撤销都不变。级别只保存在目标端，随时可以修改；修改对之后开始的回合生效，进行中的任务可以由主人取消。
- **子智能体与外部智能体**：继承委派标记与连接的信任级别，不能借此绕过限制；普通级别下不能选择被禁止的智能体类型（例如电脑操作类智能体）。外部智能体在该任务的工作目录中运行，权限请求经 Dispatch 权限邮箱由主人审批。任务被取消或连接被撤销时一并停止。
- **不能多跳**：外部任务中不暴露远程委派能力，从结构上避免跨设备、跨账号的循环委派。

### D10 不改写助理

无论信任级别，外部任务都不能改变这个助理之后的行为：

- 不参与记忆的提取与整理；
- 整个助理工作区只读（包括人设文件、`BOOTSTRAP.md` 与工作区指令文件），任务写文件写在它独立的工作目录中；
- 外部任务的会话由 Dispatch 任务单一写入，桌面端把它作为该助理名下的会话展示，标明来源账号与设备，不与工作进程共同写入助理的会话存储。

### D11 远程场景对照

- **远程控制**：发起方或目标主人用手机端、IM 驱动时，委派、等待、取消、审批都经过内核与权限邮箱。
- **Peer Device Mode**：在对端主机上发起时，出站记录和观察器属于对端主机。开放、信任设置与助理名下的外部任务属于本机目标端的数据，在 Peer Device Mode 中明确显示不支持，不回退到控制端本地数据。
- **远程工作区（SSH）**：外部任务在目标端本机运行，不涉及发起方的远程工作区。

## 分阶段交付

每个阶段单独制定开发计划，都需要审批：

1. 同账号委派与 Dispatch 能力协商（已交付）。
2. 工作进程的外部智能体执行能力与权限邮箱（已交付）。
3. 跨账号：连接与配对、连接级密钥、relay 路由授权、按连接授权、目标端审批、额度与审计（已交付）。
4. 收敛到基准（F002-07）：只开放助理；删除模式与外部智能体开放项、编码任务；连接的信任级别；外部任务以助理身份运行、不改写助理；助理名下的外部任务会话。

## 已考虑的替代方案

1. **新建点对点组网与消息邮箱（OpenBot 方案）**：语义灵活，但要重做幂等、恢复、审批与协商，与 Dispatch 重复。执行层未采用；配对与授权借鉴了它的邀请思路。
2. **跨账号共享账号主密钥，或把对方加为同账号设备**：权限无法收窄，撤销困难。未采用。
3. **由 WebRTC 直连代替 relay**：要新增 NAT 穿透与新的传输栈。首期未采用。
4. **保留模式与外部智能体开放项（放进「高级」）**：不服务于基准，主人看不懂也用不上。第 4 版删除。
5. **按授权选择记忆范围（仅人设 / 人设与记忆），叠加按开放项允许外部智能体与完全信任**：主人要理解几套交叉的开关，而且「仅人设」只有禁止命令执行才成立，违背需求第 3、4 条。改为每个连接两个信任级别。
6. **每个任务把助理复制成临时快照运行**：会话无法显示在助理下，人设更新也不同步。未采用。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 其他账号经委派对目标机器发起提示注入或越权操作 | 默认不开放、不授权；不可信输入标注；普通级别的工具限制；目标主人审批；审计；可随时撤销 |
| 连接密钥或身份被冒用 | 设备身份密钥对，配对时核对指纹；连接级密钥；撤销后 relay 立即拒绝路由 |
| relay 或对方客户端版本不一致 | 能力协商；不支持时入口显示不可用；旧版发起方的编码任务与已删除的开放项被明确拒绝 |
| 对方通过提问让助理泄露主人信息 | 普通级别不把记忆与 `USER.md` 放进提示，文件工具读取它们需审批，命令与外部智能体按审批处理；如实提示这层保护依靠审批；完全信任需确认 |
| 对方的任务改变助理之后的行为 | 不参与记忆整理；助理工作区只读；会话标明来源 |
| 完全信任的连接被注入或对方设备失窃 | 默认普通；开启前说明风险并确认；审批、额度、审计照常；随时可以改回或撤销 |
| 外部智能体消耗主人的服务商额度或违反条款 | 开放助理时按智能体提示并确认；建议使用 API Key；凭据不出设备；额度与审计 |
| 资源滥用 | 按连接设置并发和时长额度；审计；撤销 |
| 发起方离线导致结果丢失 | 出站记录持久化，重新上线后补收 |
| 工作进程与桌面端同时写入助理的会话存储 | 会话由 Dispatch 任务单一写入，桌面端只展示 |

## 兼容性、安全与回滚

- **协议**：Dispatch v6 现有动词语义不变；开放助理以新的协商能力声明；旧版工作进程不认识助理开放项的标识，会明确拒绝，不会被当作普通模式执行。
- **持久化**：连接、授权、开放清单与审计的已有记录照常读取；助理开放项与连接的信任级别是可选的新字段，旧连接视为普通；已删除类型的开放记录保留、标为不支持，不自动删除。
- **回滚**：撤回能力声明即停止对外开放；关闭 relay 跨账号路由即停止全部跨账号委派。

## 依赖

- F001：统一子智能体寻址、后台委派生命周期、外部智能体执行能力下沉。

## 批准条件（可观察）

1. 目标设备未开放、未授权时，发起方看不到其助理；同账号开放后可见；跨账号必须先完成配对，并授权后才可见。
2. 发起方把任务后台委派给远程助理：发起方助理立即继续；结果回到发起会话；关闭再重新打开发起方，结果仍能补收。
3. 外部任务在目标端是该助理名下标明来源的独立会话，回答体现该助理的人设；追问延续同一会话；主人能在那里（以及手机端、IM）处理审批；跨账号时发起方显示「等待对方审批」。
4. 助理处理外部任务时可以使用工具、创建子智能体，并在主人确认额度与条款后调用外部智能体。
