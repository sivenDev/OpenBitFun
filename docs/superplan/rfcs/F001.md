# F001 RFC：外部智能体作为可见、可后台委派的智能体

## 摘要

把通过 ACP 接入的外部智能体（首个目标为 Claude Code）提升为智能体内核中的一等委派目标：在智能体列表中可见并显示可用状态；助理通过现有 `Task` 子智能体机制委派任务，支持后台运行、`AgentWait` 取回结果、追加指令与真正生效的取消；委派过程作为可打开的子会话保留完整过程。传输继续使用 ACP，执行侧抽象为可替换的「外部智能体执行器」，为将来按需增加 Claude Agent SDK 执行器预留扩展口。本 RFC 定义的「智能体目录 + 异步委派」抽象同时是 F002（跨设备组网）的本机基础。

## 背景与问题

当前实现（基于 `main`，2f2ffe37c 之后）：

- 启用的 ACP 客户端被注册为工具 `acp__<client>__prompt`，除 minimal 外的模式会自动获得它。调用是同步的：工具一直等待 Claude Code 本轮结束，期间主智能体阻塞；没有后台选项，不可并发，默认无超时，只把拼接后的文本返回给主智能体，Claude Code 的工具调用和文件改动对主智能体与用户都不可见。
- 智能体列表只展示模式、内置/用户/项目子智能体和外部来源导入的子智能体定义；ACP 客户端以工具身份存在，不出现在列表中。
- 独立的 ACP 会话（`acp:<client>`）由桌面端宿主命令直接驱动并发出界面事件，不经过智能体内核的会话与调度器。CLI 宿主只在 `acp` 子命令中使用 ACP 客户端，CLI 智能体会话与 Detached Dispatch 工作进程中没有 ACP 委派能力（待实现阶段核实）。
- 桌面端取消对话时会向 ACP 会话发送取消通知，但找到 ACP 会话后提前返回；其他宿主与远程控制路径的取消级联未核实。
- `acp__<client>__prompt` 在远程工作区中明确不可用；独立 ACP 会话的流式路径已支持远程连接参数。

问题：用户在助理中布置任务后，希望交给 Claude Code 在后台完成、主助理不被阻塞、结果回到助理、可随时取消，并能在智能体列表中看到 Claude Code。

## 目标

1. 启用的 ACP 外部智能体出现在智能体列表中，展示可用状态：未启用、未安装或探测失败、当前工作区不支持。
2. 助理可以把任务委派给外部智能体并选择后台运行；后台运行时主智能体立即继续，结果通过与原生子智能体相同的方式取回。
3. 委派过程是一个可打开的子会话，用户能看到外部智能体的消息、工具调用、文件改动和权限请求。
4. 取消主会话这一轮、或单独取消该委派时，外部智能体实际停止；取消结果对主智能体可见。
5. 外部智能体发起的权限请求能到达当前驱动界面，包括手机端与 IM 远程控制。
6. 本机与 SSH 远程工作区行为一致；不支持的场景明确显示原因，不静默回退到本地。

## 非目标

- 不替代或改变现有的独立 ACP 会话入口与其交互。
- 不新增 Claude Agent SDK 执行器；只预留扩展口。
- 不让外部智能体反向委派 OpenBitFun 智能体（不向外部智能体注入委派工具）。
- 不做跨设备委派（属于 F002）。
- 不读取、复制或保存 Claude 的登录凭据，不提供 Claude.ai 登录。

## 决策

### D1 传输：ACP 为主，执行器可替换

外部智能体执行抽象为内核侧端口「外部智能体执行器」，能力至少包括：开始/恢复一个与 OpenBitFun 子会话绑定的外部会话、发送一轮提示并以流式事件返回、追加输入、取消、关闭。首个且唯一的实现是现有 ACP 客户端。理由：`claude-agent-acp` 本身构建在 Claude Agent SDK 之上，引擎相同；阻塞、不可见、不可取消都属于 OpenBitFun 调度层问题。直接 SDK 需要额外的 Node/Bun 进程、远程与无界面宿主的安装负担，以及第二条维护路径。只有在测得 ACP 缺少关键能力时，才另立 RFC 增加 SDK 执行器。

### D2 委派入口统一到 `Task`

外部智能体作为 `Task` 的子智能体类型被寻址，类型标识沿用会话已使用的 `acp:<client_id>` 形式。它复用原生子智能体的全部生命周期：前台或后台运行、`AgentWait`、`send_input`、`cancel`、超时与父子关系记录。外部智能体子会话不支持 `fork_context`，请求时明确报错。

兼容：`acp__<client>__prompt` 不再暴露给模型，但保留其历史工具卡片渲染与结果解析，旧会话可正常回放；配置字段 `subagent.enabled` 的语义不变，继续决定该客户端能否被委派。

### D3 ACP 回合执行下沉为宿主中立的运行时能力

为了让子会话由内核调度器运行，并在桌面、CLI 和远程控制下行为一致，ACP 回合执行从桌面宿主命令迁移到宿主中立的运行时服务；宿主只负责事件投递。这是运行时所有权迁移：按仓库规则保留旧路径兼容，用行为等价测试覆盖独立 ACP 会话的事件序列，迁移完成前独立会话入口继续走旧路径。

### D4 智能体列表

外部智能体以独立的执行方式标记出现在列表中，不向已持久化、跨版本传输的子智能体来源枚举新增取值（旧版本读者无法解析新取值）；新增字段带默认值，旧数据和旧对端忽略即可。列表项展示可用状态与原因，详情页链接到外部智能体设置；首期不在列表中提供启用开关，启用仍在设置页完成。

### D5 结果与可见性

`AgentWait` 返回外部智能体的最终回答，以及本次改动文件的摘要；完整过程保存在子会话中，可从父会话的工具卡片进入。子会话持久化复用现有 ACP 会话记录形态，带父会话关联字段。

### D6 取消级联

父会话这一轮的取消会级联到其所有进行中的外部智能体子会话，并向外部智能体发送 ACP 取消；单独取消某个委派只影响该子会话。修正桌面端取消入口「命中 ACP 会话即提前返回」的语义，使父回合与子会话的取消各自生效。取消在所有宿主和远程控制路径上走同一内核入口。

### D7 权限与交互

外部智能体的权限请求进入现有权限邮箱，带上子会话与父会话标识，后台运行时也通知到当前驱动界面，并可以从远端回答。沿用客户端已配置的权限模式（询问、本次允许、本次拒绝）；后台子会话等待权限时，父会话可见其处于等待审批状态。

### D8 远程场景

- 远程工作区（SSH）：通过现有 ACP 远程连接路径在远程主机上启动外部智能体；远程主机未安装或探测失败时，列表与委派均返回明确的不可用原因。
- 远程控制（手机端、IM）：委派、等待、取消、权限回答走内核与权限邮箱，不依赖桌面窗口。
- Peer Device Mode：外部智能体在对端主机上运行，并使用对端主机的登录。
- Detached Dispatch：首期在 Dispatch 工作进程中把外部智能体委派标为不支持并明确报错；启用它需要协商的目标能力，作为后续工作。

### D9 资源与并发

每个外部智能体子会话对应一个独立的外部会话，可以并行运行。不新增按次数的硬编码上限，沿用现有子智能体并发与超时策略；空闲外部会话按现有生命周期回收，再次使用时恢复。

## 已考虑的替代方案

1. **直接使用 Claude Agent SDK（OpenBot 方案）**：可以进程内注入工具，事件更丰富；但需要 Node/Bun 进程与远程安装，路径只适用于 Claude Code。未采用，保留扩展口（见 D1）。
2. **保留独立工具，只给它加后台参数**：改动小，但会形成第二套后台、等待、取消语义，过程仍不可见，F002 也无法复用。未采用。
3. **在终端中嵌入 Claude Code 界面**：体验与终端一致，但内核拿不到结构化事件，远程控制、权限转发和结果回收都无法实现。未采用。
4. **借鉴 OpenBot 的异步邮箱，智能体互发消息**：适合多个长期存在的智能体协作，但在本仓库会与 `Task` 后台机制和权限邮箱重复。F001 不采用；跨设备的消息语义在 F002 中评估。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| D3 迁移改变独立 ACP 会话的行为 | 先建立事件序列等价测试；迁移完成前保留旧路径；独立会话切换需单独验证 |
| 跨版本：新字段或新子智能体类型被旧对端误读 | 新增字段带默认值，不扩展已有枚举；对端能力不足时不展示、不委派 |
| 旧会话中的 `acp__…__prompt` 工具卡片无法回放 | 保留历史渲染与解析，用旧载荷回放测试覆盖 |
| 后台外部智能体进程占用内存 | 复用空闲回收；列表和父会话显示运行中的委派，方便用户取消 |
| 外部智能体在后台等待权限导致任务卡住 | 权限请求带父会话标识推送到驱动界面；父会话显示等待状态 |
| 取消未传到外部进程 | 取消级联走统一内核入口；分宿主测试取消后外部会话确实结束 |
| 使用条款 | 不接触 Claude 凭据；登录只走 Anthropic 官方流程或用户自己的 API Key |

## 兼容性与回滚

- 持久化：子会话记录、父子关联和列表新增字段都是可选字段，旧数据可以正常读取。
- 配置：`acpClients` 的结构不变。
- 回滚：关闭新的委派入口后，恢复向模型暴露 `acp__…__prompt` 即回到当前行为；已产生的子会话仍可作为普通 ACP 会话打开。

## 批准条件（可观察）

1. 启用 Claude Code 后，智能体列表中可见 Claude Code 及其可用状态；未启用时不显示；未安装或远程工作区不可用时显示具体原因。
2. 在助理会话中要求后台委派任务给 Claude Code：助理立即得到后台任务标识并继续响应；稍后通过 `AgentWait` 取回结果，结果包含最终回答与改动文件摘要。
3. 从父会话可以打开该委派的子会话，看到 Claude Code 的工具调用与文件改动。
4. 在委派运行中取消父会话这一轮或取消该委派，Claude Code 的外部会话实际停止，父会话收到取消结果。
5. 后台委派触发权限请求时，桌面端与手机端都能看到并回答，回答后任务继续。
6. 在 SSH 远程工作区中，委派在远程主机上执行；远程主机缺少 Claude Code 时返回明确错误，不在本地执行。
7. 包含旧 `acp__…__prompt` 调用的历史会话可以正常打开和显示。
8. 独立 ACP 会话入口的行为不变。
