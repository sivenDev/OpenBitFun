# Features

> 功能需求清单（人工维护）。每条需求一个 `## ` 小节，编号 `F001`、`F002` … 顺序递增、不复用；linked worktree 中自动编号会追加分支限定，如 `F001@branch-slug`。
>
> 录入方式：对 AI 说“新建 feature: <标题>”，或手动复制下方模板。
>
> `status`：`proposed`（默认，待人工复核）→ `accepted`（已确认、可规划）→ `done`（已交付）。仅当用户明确授权录入并继续规划、内容忠实且不存在实质歧义时，AI 才可直接记录为 `accepted`；否则保持 `proposed` 并等待复核。`accepted` 只批准规划，不批准实施。
>
> 正文只记录需求意图。能说清时用一段话概括要做什么、主要范围、验收结果和关键限制；设计决策、替代方案与风险论证留给 RFC，执行任务留给 plan。
>
> `requires_rfc: true` 为可选字段，缺失时按 `false`。人类明确要求或 AI 说明实质设计风险后可启用；需要 RFC 的 feature 必须先完成独立设计审批，再进入计划审批，具体格式由 Superplan RFC 流程管理。

## F001: 助理可委派任务给 Claude Code 智能体，并在智能体列表中显示

- status: accepted
- created: 2026-10-29
- requires_rfc: true

范围：在设置中启用 Claude Code ACP 后，用户在助理会话中安排任务，助理能把任务委派给 Claude Code 智能体在后台异步执行，Claude Code 同时作为一个智能体出现在智能体列表中；验收：启用后智能体列表可见 Claude Code 及其可用状态；助理会话中下达任务后由 Claude Code 在后台执行，助理不被阻塞，结果完成后回到助理会话；取消助理或该委派时 Claude Code 实际停止；未启用 ACP 时不显示、不可调用；限制或非目标：不替代现有的独立 Claude Code ACP 会话入口；作为后续跨设备智能体组网（F002）的本机基础。

## F002: AI协作：在局域网内共享助理

- status: accepted
- created: 2026-10-29
- requires_rfc: true

范围：主人在「助理」页把自己的助理设为共享（设置信任程度、会话保留天数、同时处理的任务数）；同一局域网的其他 OpenBitFun 用户点「发现」看到共享的助理（设备名 + 助理名）并申请使用，主人当场在带倒计时的确认框中同意，结果经局域网直接推送；被授权的助理进入使用者的助理列表、标明来源、点开直接对话，每个对话在主人那边是该助理名下标明来源的独立会话；助理之间可以相互调用（自己的助理与别人共享给我的助理）；不需要登录账号，不经过中继。验收：不登录的两台设备在同一局域网完成共享、发现、申请确认、对话、审批、撤销；超时自动拒绝；对方不在线、本地网络权限被拒、版本不兼容、已撤销、超出同时任务数时明确说明原因；助理间调用成环时拒绝。限制或非目标：只在局域网内，不做跨网络或经中继的共享；删除 AI协作页与中继跨账号连接；依赖 F001。

## F003: 助理的空会话可以删除

- status: done
- created: 2026-11-05

范围：所有本机助理（含主助理）名下新建、还没发出过任何一轮对话的空会话，在会话菜单里可以直接删除，无需确认；有内容的会话仍走「归档 → 在已归档会话中删除」。验收：空会话菜单出现「删除」，点击后从列表与主机上消失；删除的是该助理的默认会话时清除默认设置；删除的是正在打开的会话时切换到别的会话；远程工作区与 Peer Device Mode 下同样可用，经现有删除接口执行；有内容的会话不出现该项。限制或非目标：不改项目会话；共享助理上的对话删除在 F002-18 中处理。
